# 번역 방침

## 문체

화자에 따라 세 갈래로 나눈다.

### 1. 조수 — 해요체 (정중하지만 부드럽게)

플레이어를 돕는 조수는 옆에서 거드는 동료지 상관이 아니다. 정중하되 딱딱하지 않게.
`hints`와 `query-hints` TextAsset이 여기 해당한다.

- 좋음: "사건을 해결할수록 다음 장(챕터)이 열려요."
- 좋음: "지금 화면에서는 쿼리를 작성할 필요는 없어 보이는데요?"
- 나쁨: "사건을 더 해결하면 새 챕터가 열린다!" (반말이라 조수 말투로 안 맞음)
- 나쁨: "챕터를 해금하시려면 사건을 해결하시기 바랍니다." (과하게 격식)

### 2. 시스템·오류 메시지 — 합니다체

CopOS가 내보내는 알림, 파서 오류, 확인 대화상자. 감정 없이 사실만.
`dynamic.json`, `patterns.json`이 여기 해당한다.

- "'notepad' 테이블을 찾을 수 없습니다. 테이블 이름이 맞는지 확인하세요."
- "종료하시겠습니까? 진행 상황은 자동으로 저장됩니다."

### 3. 그 외 등장인물·게임 내 게시글 — 반말 누아르 하드보일드

포럼 글, 댓글, 뉴스, 인물 대사. 건조하고 짧게 끊는다.
감탄사와 미사여구를 줄이고 명사로 끝맺는 문장을 섞는다.

- 좋음: "그놈 잡았어. 기록 남겨둬."
- 나쁨: "그 사람을 검거하였습니다. 기록을 남겨주시기 바랍니다."

예외로 게임 내 웹사이트의 공식 안내문·법적 문구는 원문이 격식체면 격식체를 유지한다.

## UI 길이

한글은 같은 뜻이라도 글자 폭이 넓어 원문보다 길어지기 쉽다.
버튼, 라벨, 창 제목은 **원문보다 길어지지 않게** 줄인다.

- "Save Table" → "저장" ("테이블 저장"은 라벨 영역을 넘쳐 옆 요소를 덮었다)
- "Page 1" → "1p" ("1쪽"보다 좁고 원문 감각에 가깝다)

좁은 자리에서는 뜻을 다 담기보다 짧게 쓰는 쪽을 택한다. 맥락은 화면이 알려준다.

## 고유명사

**영문 표기를 그대로 둔다.** 인물명, 회사명, 지명, 제품명 모두 해당한다.

이 게임은 플레이어가 SQL로 데이터를 조회해 사건을 푼다.
조회 결과에 뜨는 이름과 대사 속 이름의 표기가 다르면 단서를 연결하지 못한다.
따라서 `Akira Watanabe`, `Annadale Farm` 같은 값은 번역하지 않고 비워둔다.
(번역이 비어 있으면 원문이 그대로 표시된다.)

## 번역하지 않는 것

SQL 조회 대상은 전부 원문 유지. 번역하면 쿼리가 통하지 않아 게임이 깨진다.

- 테이블 이름, 컬럼 이름 — UI 문자열 중에도 소문자 `exit`, `settings`처럼 실제 테이블명이 섞여 있다
- 이름·영화·작물·프로필 등 데이터 목록 (`tools/extract_text.py`의 `KEEP_ORIGINAL` 참고)
- SQL 키워드와 예시 쿼리
- 숫자, 날짜, ID, 파일명

## 서식

- `{0}`, `{1}` 같은 자리표시자는 개수와 번호를 그대로 유지한다
- `<color=...>`, `<b>` 등 리치 텍스트 태그는 그대로 둔다
- 줄바꿈 위치는 원문을 따르되, 한글이 길어져 UI를 넘치면 조정한다
- 버튼·메뉴 라벨은 짧게. 원문보다 길어지지 않게 한다
